## 이탈을 유발할 수 있는 지점과 수정

1. **가입 중 강제 로그인 이동 — 재현된 오류.** 비회원은 공개 분석 API만 호출한다. 기존 로그인 전용 계측은 인증된 대시보드에서만 실행하고 중복 페이지 조회를 제거했다.
2. **로그인 실패 시 폼 소실 — 동일 코드 경로의 오류.** 로그인·2FA 실패의 401은 화면 내 오류로 처리한다. 현재 인증 토큰을 사용한 보호 API 요청의 401만 세션 만료로 처리한다. 분석 실패는 인증 상태를 변경하지 않는다.
3. **면허증 사본을 준비하기 전 가입 불가 — 확인된 가입 장벽.** 사본을 나중에 설정에서 제출할 수 있도록 변경했다. 면허번호와 필수 동의, 서버 검수·기능 접근 정책은 유지한다. 누락 항목은 제출 시 안내하며 입력값을 분석 서버에 전송하지 않는다.
4. **사본 업로드 실패 시 잘못된 경로.** `/settings` 대신 실제 경로 `/dashboard/settings?license=upload-failed`로 이동한다.
5. **광고 페이지와 현재 제품 안내 불일치.** `/go`, `/start`, `/trial`을 현재 랜딩과 동일한 제품 체험·요금 안내로 연결했다. 별도 광고 화면의 14일 체험 문구·과거 후기·효과 표현을 독립적으로 유지하지 않는다. UTM은 동일 브라우저 세션으로 가입까지 이어진다.
6. **비회원 유입 관측 불가.** 기존 랜딩 기록은 선택적인 `gtag` 호출과 브라우저 보관에 그쳤다. 이제 자체 수집 API에 저장한다.
7. **재배포 시 관리자 비밀번호 덮어쓰기.** 후속 운영 반영 과정에서 발견해 수정했다. 서버가 시작돼도 기존 관리자의 비밀번호·정지 상태를 변경하지 않으며, 초기 관리자 정보가 명시적으로 설정되지 않으면 기본 비밀번호로 계정을 생성하지 않는다.

광고 매체·집행 시작일·도착 URL·클릭 수·광고비는 제공되지 않았다. 광고 타기팅, 소재 적합도, 매체별 실제 전환율과 CPA는 아직 판단할 수 없다. 과거 비회원 이탈률과 히트맵도 소급 복원할 수 없다.

### 집계 기준과 한계

- 방문자는 무작위 브라우저 식별자이며 실제 개인 수가 아니다. 다른 기기·브라우저는 연결하지 않는다.
- 세션은 30분 비활동으로 종료한다. 진행 중 세션은 이탈률 분모에서 제외한다.
- 이탈: 종료 세션 중 페이지 조회 1회 이하, 참여 10초 미만, 가입/데모 완료/기능 사용 없음.
- 참여 시간: 보이는 탭에서 측정한 누적 시간. 같은 화면의 주기적 전송을 합산하지 않고 최댓값으로 계산한다.
- 가입은 성공 API 응답을 받은 브라우저의 기록이다. 서버 계정 수와 비교해야 한다. 차단 프로그램·네트워크 실패·기기 변경으로 누락될 수 있다.
- 기능 사용은 지정한 처방 추천·치험례 검색·AI 분석 API의 성공 응답 기준이다. 모든 기능을 포괄하지 않는다.
- 전환 단계는 같은 세션 내 순서를 요구한다. 다음 날 복귀 가입과 기간 경계의 이전 단계는 포함되지 않을 수 있다.
- 히트맵은 문서 전체의 가로·세로를 정규화한 5% 격자 밀도다. 실제 화면 캡처 위에 겹치는 녹화가 아니다. 화면 크기·페이지 길이·레이아웃 변경에 영향을 받는다.
- 데이터가 50,000이벤트를 넘으면 기간 축소를 요청한다. 잘린 표본으로 비율을 계산하지 않는다.
- 광고비 연동이 없어 CPA/ROAS는 계산하지 않는다. raw 광고 클릭 ID, 검색어, 전체 referrer URL은 저장하지 않는다.

### 수집·보관

공개 수집: `POST /api/v1/analytics/growth/events`. 관리자 보고: `GET /api/v1/admin/growth`.

기존 `analytics_events`에 `growth_` 접두사 이벤트를 저장하므로 이번 변경 자체에는 스키마 마이그레이션이 없다. 이벤트 UUID로 중복 전송을 방지하며 배치 최대 50개, 허용 이벤트/페이지/필드/좌표/시간을 서버에서 검증한다. 저장 실패를 성공으로 응답하지 않는다. 요청 제한은 기존 전역 throttler와 공개 경로 제한을 적용한다.

폼 값·DOM 텍스트·비밀번호·면허증·진료 내용·상세 환자 URL·관리자 클릭을 수집하지 않는다. 브라우저 DNT/GPC 및 개인정보처리방침의 분석 거부 설정을 반영한다. 식별자와 이벤트는 90일 기준이며 새 분석 이벤트만 매일 한국 시간 오전 4시에 정리한다. 기존 운영 분석 기록에는 정리 작업을 적용하지 않는다.

## 개선 순서

1. 재현된 강제 이동 오류를 운영에 반영하고 가입 폼 유지 여부 확인.
2. 광고 URL에 예: `?utm_source=meta&utm_medium=cpc&utm_campaign=clinic_sep&utm_content=case_demo` 부여.
3. 관리자에서 방문 → 입력 시작이 낮으면 광고 메시지/첫 화면/체험 CTA를 비교.
4. 입력 시작 → 요청이 낮으면 필수 입력과 모바일 폼을 점검. 요청 → 성공이 낮으면 오류 코드 우선 해결.
5. 가입 → 첫 사용이 낮으면 샘플 진료·치험례 검색까지 직접 안내. 개선 전후 동일 조건의 방문과 계정 수를 비교.
